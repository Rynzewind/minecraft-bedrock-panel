# Add-on updater verification — 28 October 2026

The approved design is in `superpowers/specs/2026-10-28-addon-updates-design.md`. A fresh reviewer inspected the complete branch before release. The fix pass added regression tests for all six Critical/Important findings: unsafe manifest UUID paths, unknown legacy deployed versions, retained companion manifest validation, installer historical path rebasing, disabled target preservation and provider release acknowledgement only after successful staging. An additional regression rejects new dependent packs masquerading as required companions.

Verification covers per-server version pinning, stale archive/state rejection, transactional rollback/retry, engine guards, paired dependencies, DPAPI storage, snapshot exclusions, official API pagination/game/channel checks, sanitized failures, distribution restrictions, CDN key isolation/checksums, maintenance interlocks and native masked controls/explicit targets. Live CurseForge access remains unverified until an approved developer key is entered by the operator. Live native screenshot capture was unavailable; control/layout tests do not replace operator visual acceptance.

Implementation choices: checks are on demand; the installer contains no key and key entry occurs after installation; eligible API candidates are limited to the latest 100 after pagination. These choices avoid background activation and oversized local API responses. The source page remains available for older files. An update cannot target a disabled selected pack; enable it separately first. Unknown legacy deployment versions block implicit Apply until explicitly selected.

Deferred minor observations from review: the confirmation lists exact versions and per-server actions but does not expand engine/dependency constraints; JSON `null` source settings are interpreted as an empty legacy map; a source-check metadata write concurrent with a snapshot can require a snapshot retry. None is reported as proof that an add-on is current.
